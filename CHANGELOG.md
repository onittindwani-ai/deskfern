# Changelog

## 1.0.1 (2026-11-25)

- Hardening after a security review. A message's sender is now checked: an email sender counts as verified only when your mail provider (`INBOUND_AUTHSERV_ID`) wrote a passing DMARC result, and a helpdesk channel only when you list it in `TRUSTED_SENDER_CHANNELS`. An unverified sender is never matched to a customer, so no account or payment fact is used for it, and the reply asks the person to confirm. A person confirms on the ticket.
- One broken message no longer stops the rest. A message with an unreadable character set, a very long Message-ID or text a database refuses is skipped on its own, mail is read without marking it read and marked read only after it is stored, and customer words are no longer written into logs or job errors.
- Replies leave the way the ticket came in: an email ticket is answered by the email adapter in its thread, a helpdesk ticket through its helpdesk, and a reply that could not be sent is no longer recorded as sent. A second reply to the same ticket is refused. The Pause all switch and draft mode are read from the database on every send.
- Sign in: the address is compared without spaces or capitals, sign in is limited per visitor, per address and per account, and an unknown address costs the same work as a wrong password. The public demo logins and demo buttons switch off by themselves once `OWNER_PASSWORD_HASH` is set. The API and worker refuse to start on an example `SESSION_SECRET` outside the demo, and a live start is refused while the company name, owner address or sender address is an example or no reply could be sent.
- Email and web: certificates are checked on both mail connections and plain text is allowed only to this computer; webhook and web proxy bodies are read in small pieces and refused over `MAX_BODY_BYTES`; the web proxy takes the visitor address from the last hop only.
- A real install works end to end: import customers from a CSV file (`python -m deskfern.admin import-customers`), read the `KNOWLEDGE_DIR` folder from the Knowledge page or the command line, and set your company, currency, sender and owner as settings. Every setting is in `.env.example` and `docs/04-ENVIRONMENT-VARIABLES.md`, and a test fails when they drift apart. The API, worker, database migration and admin commands read the same settings file (`ENV_FILE`).
- Deploy: the Caddy API host serves only the Chatwoot webhook and `/health`; the Hetzner backup keeps the knowledge folder and refuses an empty dump. Docs say plainly what was and was not run.
- Second independent review of the hardened repo, all findings fixed, each with a test:
  - A real `SESSION_SECRET` is now required whenever an owner password is set, `MODE` is live or `DEMO_MODE` is off. Before, a demo flag left on next to an owner password and the example secret let anyone make an owner session token. The app and the worker refuse to start; the same check exists in the shared base from 1.2.5 and is said once.
  - A hostile message can no longer stall the worker: a pattern in the injection scan took 4 seconds on 20,000 dashes and 12 seconds with one phrase added. Patterns are bounded, long runs of one character are squeezed, scans are cut to 20,000 characters, and HTML comments are found by string search. Hostile strings are tested under a time limit through triage and the whole drafting path.
  - A refund approved while draft mode or Pause all was on is now paid later: the worker checks every minute, and the Approvals page has Pay approved refunds now. It is claimed with one conditional update so two callers cannot both pay, it is audited, and a failing payment system leaves it waiting. A second ticket about that payment is closed with a note that says where the refund stands.
  - Sign in: the account wide limit counts failed tries only and never holds up an address that signed in as that account in the last 24 hours, so someone who only knows the owner's email can no longer keep the owner out. The remaining risk (a first sign in from a new address waits during an attack) is written in `SECURITY.md` and the docs.
  - A refund drafted by pressing Draft again or Confirm sender is asked in that person's name, so they cannot approve it; a live install with a real payment system needs `APPROVER_EMAIL` and its hash or it refuses to start. Secret settings no longer show in the settings text.
  - Crawling: a site's Crawl-delay is capped at 10 seconds, one page may take at most 30 seconds, the whole crawl has a time limit and a size limit (`CRAWL_DEADLINE_S`, `CRAWL_TOTAL_BYTES`), and a real site is crawled by the worker; the Knowledge page waits and shows the progress.
  - Replies: the answer is claimed and saved before anything leaves, a timeout or dropped connection becomes a clear message (not a 500), and a send that may have been delivered waits for a person to say whether the customer got it (It was delivered, It was not delivered) instead of being sent again. A reply stopped by draft mode or Pause all is held: the ticket stays open and its reply clock keeps running, where it used to be marked answered.
  - Smaller: the web proxy refuses path segments that hold anything but letters, digits and `. _ ~ -` (`auth/login?` reached the login route); Intercom, Zendesk and Freshdesk lists are read up to 5 pages per run; a mailbox run takes at most 50 messages and skips any over 2 MB; a mail with only an HTML part gives the ticket its words; the ticket search runs in the database before the row limit; `make constraints` exists and `make test` runs the web unit tests.
- Tests: 175 new tests in this release (333 pass, 2 skipped, 93.7 percent coverage). Nothing that tested a safe behaviour was removed. Older tests that expected the earlier unsafe behaviour were changed to the new rule: mail marked read on fetch, a payment made without being asked in a non demo setup, a draft mode reply that marked the ticket answered (`test_api.py`), and the Pause all test that edited the database by hand to retry a refund and a reply (`test_hardening_send.py`, now using the real retry route). Two browser test labels changed with the refund status wording (`demo-path.spec.ts`, `round5.spec.ts`); the browser tests were not run here.

## Earlier changes in this release

- Second walk through every screen in a real browser. The demo bar (Run now, +1 day) now shows in draft mode and Run now brings in a new fictional ticket each press. Sign in returns to the page that was asked for. Pause all and Sign out stay in the top bar on a phone, and the kill switch button says "Turn it off" while it is on. G then a number works. A viewer sees write buttons switched off with a reason instead of errors. Ticket names open the ticket by tap. Approving a refund says whether anything was paid, and the ticket leaves the Refunds list. One refund request per payment (two tickets about the same payment can no longer both be approved), a paid refund is never requested again, handing a ticket over twice keeps one record, crawling the same address twice does not double the pages, a dismissed gap stays dismissed, gap labels are the customer's own words. Reset keeps the tables, so pages refreshing during a reset no longer answer 500. The confidence ring and the Insights ring show the real share. Plain labels replace internal names. A question like "If I cancel, do I get money back?" is no longer treated as a refund request. 23 browser tests and 16 Python tests were added, one per fix.
- Shared base updated to 1.2.0. Optional read only `viewer` login (`VIEWER_EMAIL`), the person who asked for an approval can no longer decide it (the base now enforces it, the route's own copy of that check is gone), `LLM_BACKEND` (offline, fixture, anthropic) chooses the model path, `LOGIN_BURST` sets the sign in burst (browser tests raise it). The offline stand in answer writer now sits behind the base model wrapper (`offline_llm.py`).
- First reply deadlines count business hours by default (09:00 to 17:00, Monday to Friday, in `OFFICE_TIMEZONE`). `SLA_CLOCK=round_the_clock` counts every hour. A ticket that arrives when the office is closed starts its clock at the next opening.
- The `[NEEDS FOUNDER FACT]` tags are replaced by the decided defaults (refunds 7 days monthly and 14 days annual, one per customer per 12 months, duplicate charges always refunded, every refund approved by a person; reply targets 1, 4, 24 and 72 hours; plain, friendly, short tone), each with a note that the implementer can change it.
- Renamed from Lighthouse to Deskfern after a public name check. The Python package, environment variable prefix, interface text, documents, prompts, templates and screenshots all use the new name.

## 1.0.0
